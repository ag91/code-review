#+TITLE: Improvements plan for code-review mode

Goal: make reviewing AI-generated PRs from Emacs practical. See the
*important* changes early, keep noise away, and review inside real
repository context (xref, tests, running code).

* Phase 1 — Local repo context                                  :STATUS:done

The mode has no notion of "the PR's repository on disk".  Visiting a
file used =(magit-toplevel)= on the *review buffer*, which only works
when you happened to launch from inside the repo.  Fix: resolve,
clone if needed, fetch PR refs, and check out a worktree.

- New file =code-review-repo.el=:
  - =code-review-projects-root=: default dir to look for clones
    (~ =nil= disables).  Matches clones by git remote URL, one and
    two levels deep, plus the current =magit-toplevel=.
  - On-demand clones (=git clone --filter=blob:none=, prompted) go
    under =code-review-projects-root= (or =/tmp=) directly at
    =ROOT/REPO= (just the repository name).  Per-PR worktrees live
    inside the clone's git directory (=.git/code-review-worktrees/N=),
    so they never pollute the working tree and survive =git clean=.
  - Fetch =pull/N/head= (GitHub) or =merge-requests/N/head= (GitLab)
    into =refs/remotes/code-review/N/head=, plus the base ref.
  - =git worktree add --detach= at the PR head, hard-updated on
    refresh when the PR is force-pushed.
- Review buffer gets =default-directory= set to the worktree, so
  =project.el=, compile, grep, eglot etc. work against the exact PR
  version.  A "Worktree:" header shows it (clickable, opens Dired);
  =w= opens the worktree.

* Phase 2 — Transparent xref in the diff                          :STATUS:done

- =code-review--resolve-worktree-position=: shared resolver
  (file . line) for the patch line at point (ignores comment lines
  inside hunks).
- =code-review-xref-find-definitions= / =code-review-xref-find-references=
  (=M-.= / =M-?=): symbol at point in the diff, jump to the worktree
  file at the matching line, then run the real xref command there.
  No glue: the worktree is a normal project checkout, so every xref
  backend (eglot, etags, gtags) just works.

* Phase 3 — Noise reduction                                    :STATUS:done

CONSTRAINT (why this phase is classification, not replacement):
comment anchors (=position=, =side=, =line=) refer to the API's
unified diff.  Rendering a *different* diff (e.g. a locally
generated =-w= one) misplaces or drops comments.  So the review
surface stays the API diff; noise handling only classifies, tags
and collapses.

DONE (implementation notes):

- =code-review-diff-file-order-rules= now accepts regexp strings
  (order-only, backward compatible) or plists
  =(:match REGEX :tag TAG :collapse BOOL :hide BOOL)=.
- New built-in =code-review-diff-noise-rules= (enabled by
  default, battery included; set to nil to disable): lockfiles,
  minified/build output -> =GEN=; CHANGELOG/docs/README ->
  =DOC=; all collapsed.
- =code-review--diff--classify-diff= per render: merges user
  rules, noise rules, textual detection and the worktree check
  into a hash table used by the wash (tags, collapse) and by
  focus-mode filtering.  Classification happens on every render
  and is deliberately NOT permanent-local (the re-activation of
  =code-review-mode= at the end of =code-review--trigger-hooks=
  kills buffer-locals; everything reads it during the wash, so
  this is fine).
- Whitespace-only files: textual pairwise hunk comparison
  (=code-review--diff--block-ws-only-p=) plus, when the worktree
  exists, one =git diff --no-renames -w --ignore-blank-lines
  --numstat base...HEAD= call
  (=code-review-repo-substantive-files=): files absent from the
  numstat output (all-zero) are =WS-ONLY=, collapsed + hidden in
  focus mode.  Binary/mode-only blocks are guarded via
  =code-review--diff--block-has-content-p=.
- Pure renames -> =[MOVED]=, collapsed, NOT hidden in focus mode.
- Files carrying review comments are never auto-collapsed
  (=code-review--diff--file-has-comments-p= guard in the
  =insert-file-section= override).
- Ordering: user rules first, then unmatched files, then noise
  rules last (noise sinks to the bottom of the diff).
- Focus mode: buffer-local =code-review-focus-mode= (permanent
  so it survives re-renders), =N= or the transient toggles it;
  hidden files are removed from the buffer text but always
  counted in the "Files changed" heading
  (=code-review-section--focus-summary=).
- =V=: view-only =*Code Review Diff (-w)*= buffer
  (local =git diff -w --ignore-blank-lines base...HEAD=, =diff-mode=,
  warning banner that comments cannot anchor there).
- =D=: difftastic drill-down via
  =(difftastic-git-diff-range "refs/remotes/code-review/N/base...HEAD" nil (list FILE))=
  from the worktree; =C-u D= for the whole PR.  Soft-dependency:
  friendly install hint when =difftastic= or =difft= is missing
  (both absent on this machine; the error path is tested).
- GOTCHA fixed along the way: PR 3's API diff uses NO a/ b/
  prefixes (=diff --git file file=), so
  =code-review--diff--extract-b-path= now handles both forms;
  without this every file classified under path "".
- GOTCHA: docstrings containing ='(= need =\\='= in source to
  satisfy the byte-compiler docstring check.

Original design (kept for reference):

** File rules: from ordering to classification

Extend =code-review-diff-file-order-rules= so each element is
either a regexp (backward-compatible: order-only, as today) or a
property list:

  (:match REGEX :tag "docs" :collapse t :hide t)

- =:tag= shows a =[\[DOC]]= style tag on the file heading
  (=code-review-section--magit-diff-insert-file-section= already
  overrides file sections, so heading + default hidden state are
  easy to control).
- =:collapse= starts the file section hidden.
- =:hide= omits the file entirely in "focus mode" (never silently:
  the files-changed summary counts them).
- Built-in default rules (toggleable via
  =code-review-diff-noise-rules=): lockfiles
  (=package-lock.json=, =yarn.lock=, =pnpm-lock.yaml=,
  =Cargo.lock=, =flake.lock=, ...), minified/build output,
  CHANGELOG and pure docs -> =GEN= / =DOC= tags, collapsed.

** Hunk-level classification (purely textual, no repo needed)

- Whitespace-only hunks: every =-=/=+= pair is equal after
  collapsing internal whitespace -> =[\[WS]]= tag, collapsed by
  default.  Works on the raw diff text we already split per file
  in =code-review--maybe-reorder-diff=.
- Pure renames (header has =rename from/to=, no hunks) -> one-line
  =[\[MOVED]]= section.

** Local-repo assisted classification (phase 1 gives this free)

- When the worktree is available: =git diff -w base...head -- FILE=
  empty -> whole file tagged =[\[WS-ONLY]]= and collapsed (catches
  reformatting churn the textual check misses).

** Focus mode

- A transient toggle (like the existing =toggle-display-*= ones):
  hide everything tagged =GEN= / =DOC= / =WS-ONLY=; the
  "Files changed" heading reports what is hidden
  ("6 files: 3 substantive, 2 docs, 1 generated").

** The =-w= "what really changed" view, done safely

- A view-only buffer (=*Code Review Diff (-w)*=) rendering the local
  =git diff -w --ignore-blank-lines base...head=, banner noting
  that comments cannot anchor there.  This replaces the original
  (unsafe) idea of swapping the review surface to the =-w= diff.

** Difftastic drill-down

- Optional dependency on =difftastic.el= (pkryger, MELPA): more
  robust than a hand-rolled =GIT_EXTERNAL_DIFF= runner (it is the
  maintained version of that blog code: ANSI->theme faces, width,
  reflow, chunk nav).
- Key on a file section (say =D=): run
  =difftastic-git-diff-range= on base...head for that file, from
  the worktree (=default-directory= already points there).  With
  =C-u=: whole-PR structural diff.
- Explicitly NOT in-place rendering (rschmukler/magit-difftastic
  renders inside magit buffers with staging; in-place difftastic
  would break the line anchoring comments need).

* Phase 4 — Robust GitHub data (pr-review lessons)               :STATUS:done

How /tmp/emacs-pr-review handles comments (it *does* use magit, but
only as a renderer):

- Renders the diff with public =magit-wash-sequence=
  / =magit-diff-wash-diff=.  No =advice-add= overrides of magit
  internals (code-review currently overrides
  =magit-diff-insert-file-section= and =magit-diff-wash-hunk=).
- After washing, walks the buffer once and stamps every diff line
  with =pr-review-diff-line-left/right= text properties carrying
  =((path ...) (line ...))=.  Anchoring a comment becomes an exact
  =text-property-search-forward=, not line-count arithmetic.
- Comments come from GraphQL =reviewThreads= (=path=, =diffSide=,
  =line=, =isOutdated=, =isResolved=).  In-diff fringe markers link
  to full threads; pending comments are collected buffer-locally
  and submitted as one =addPullRequestReview= mutation with a
  =threads= input.

Plan for code-review:

- Fetch comments via GraphQL =reviewThreads=; kill the
  "amount-loc"/"head-pos" line arithmetic.  Anchor by (path, side,
  line) directly.
- New comments become pending review threads, submitted in one
  mutation.  Add resolve/unresolve support.

DONE (implementation notes):

- Both GraphQL queries now fetch =reviewThreads(first: 100)= with
  =id=, =isResolved=, =isOutdated=, =path=, =diffSide=, =line=,
  =startDiffSide=, =startLine= and their comments'
  =databaseId=/=fullDatabaseId=.
  - SCHEMA GOTCHA: =side= / =startSide= do NOT exist on
    =PullRequestReviewComment= (the query errors out and you get
    zero comments).  The side lives on the *thread*
    (=diffSide=/=startDiffSide=).  =code-review-github-fix-infos=
    now merges =threadId=, =isResolved=, =side=, =startSide= and
    =line=/=startLine= fallbacks from each thread into the review
    comments, keyed by =databaseId=.
- =make-group= keying precedence: outdated -> position key (render
  from own diffHunk); has line -> exact =path:side:line= key (no
  buffer arithmetic); else legacy position key.  Comment sections
  carry =thread-id= / =resolved?= (heading shows a RESOLVED tag).
- =wash-hunk= tries both RIGHT and LEFT line keys for context
  lines.
- =R= toggles resolve/unresolve via GraphQL
  =resolveReviewThread= / =unresolveReviewThread=
  (=code-review-threads-toggle-resolved=; fallback user-error for
  other providers).
- Validated: unit tests (merge, keying for modern/outdated/legacy/
  local comments, fallback) + live against real PRs
  (wandersoncferreira/code-review#96, ag91/code-review#3 with a real
  outdated thread: thread metadata merged, comment rendered from
  its diffHunk).
- NOT done here: converting local (pending) comments to a single
  =addPullRequestReview= mutation; that needs the write path
  redesigned (see pr-review).  Current write path already uses the
  line/side API.

* Phase 5 — Duplicate and dead code detection                    :STATUS:todo

- Similar code: normalize added lines (mask strings/numbers), take
  4-line shingles, match against an index of the repo built at the
  *base* commit.  Report "18/20 added lines similar to
  src/foo.py:120-140" with a jump link.
- Dead code: (a) newly added definitions with zero references in
  the head tree -> "possibly dead"; (b) symbols deleted by the PR
  still referenced elsewhere -> "dangling reference" (this one is
  reliable).  Shown in a toggleable "Analysis" section, clearly
  marked heuristic.

* Phase 6 — Edit submitted comments and PR lifecycle          :STATUS:todo

The biggest write-path gap vs pr-review: everything it can edit
after submission.

- Edit an already-submitted remote comment
  (=updatePullRequestReviewComment=), a submitted review summary
  (=updatePullRequestReview=), and a thread item.  We can only
  edit local (pending) comments today.
- Reopen a closed PR (we only close).
- Toggle draft / mark ready for review (=convertPullRequestToDraft=,
  =markPullRequestReadyForReview=).
- Subscribe / unsubscribe / ignore PR notifications
  (=updateSubscription=).
- Consider moving the local-comments submit to a single
  =addPullRequestReview= mutation with a =threads= input (pending
  comments + replies + summary in one call), as pr-review does.

* Phase 7 — Notifications dashboard and PR search                :STATUS:todo

Cuts the GitHub-website round trips.

- =code-review-notification=: list GitHub notifications in a
  buffer, dired-style mark/act (mark read, unsubscribe), toggle
  filters, paginate.  Opening a PR from it marks read and passes
  the last-read time so newer items get a NEW highlight (pr-review
  does this by binding =pr-review--last-read-time= around the
  render).
- =code-review-search= / =code-review-search-open=: search PRs
  by GraphQL query, pick from results (completing-read or a
  listview buffer).
- =browse-url= integration: register a URL parser in
  =browse-url-default-handlers= so GitHub PR links (with file/line
  anchors) open inside Emacs; also find a PR URL in the current
  buffer (email/notmuch workflow).

* Phase 8 — Diff drill-down: ediff and base views                :STATUS:todo

Nearly free now that phase 1 gives us the worktree and the base
ref.

- =code-review-ediff-file=: ediff the changed file under point,
  worktree (head) vs =refs/remotes/code-review/N/base= checkout
  of the base version.
- View the file under point at the *base* version (currently we
  only have head, via the worktree).
- =code-review-select-commit=: narrow the reviewed diff to a
  subset of the PR commits (complement to the existing commit-focus
  buffer).
